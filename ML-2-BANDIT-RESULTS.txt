-----------------------------------------------
  NOTE ON TREND INTERPRETATION
-----------------------------------------------
  The apparent downward trend is an artifact of how the benchmark
  seeded data: tasks were inserted in ascending latency order
  (920ms first, 4520ms last) with the highest-latency tasks
  timestamped most recently. This produces a structurally falling
  reward curve because longer latency = lower latency score.

  In a real production environment the bandit explores different
  nodes and the reward trend reflects genuine learning. To measure
  actual learning:
    1. Run 100+ tasks against the live API with varied workloads
    2. Allow the epsilon-greedy bandit to explore (epsilon=0.1)
    3. Observe whether avg_reward increases as the bandit converges
       to high-scoring nodes

ONGOING MONITORING QUERY
===============================================

  Run this in Postgres to track live learning trend:

    SELECT
      DATE_TRUNC('minute', "createdAt")       AS minute,
      COUNT(*)                                AS outcomes,
      ROUND(AVG("rewardScore")::numeric, 4)  AS avg_reward,
      ROUND(MAX("rewardScore")::numeric, 4)  AS max_reward
    FROM scheduling_outcomes
    WHERE "createdAt" > NOW() - INTERVAL '1 hour'
    GROUP BY 1 ORDER BY 1;

  A rising avg_reward across consecutive minutes indicates the
  bandit is learning to prefer higher-scoring nodes.

=== SIMULATOR CONTRACT (scripts/fl-simulator.ts) ===
Round init endpoint:
  GET /v2/ml/federated/round
  Headers: Authorization: Bearer <jwt>, X-Node-ID: <node-uuid>
  Response: { roundId, roundNumber, status=RUNNING, minParticipants=3, submissionsCount }
  Auto-creates new RUNNING round after previous round reaches COMPLETED.

Weight upload endpoint:
  POST /v2/ml/federated/weights/upload  (multipart/form-data)
  Fields:
    weights      - Binary float32 buffer (50 KB, 12500 params x 4 bytes)
    roundId      - UUID of the RUNNING federated round
    nodeId       - UUID from edge_nodes.id (FK-constrained)
    sampleCount  - Integer (local training sample count)
    avgReward    - Float (local average reward signal)
  Response: { success: true, weightsUrl: "models/<key>/weights.bin" }

Aggregation trigger:
  Fires asynchronously when submissionsCount >= minParticipants (3)
  Calls FederatedAggregator.aggregate(roundId) from @edgecloud/ml-scheduler
  Marks round.status = COMPLETED
  Uploads aggregated weights to MinIO under a timestamp-keyed path

=== BUGS FOUND AND FIXED ===
1. MINIO SSE BLOCKER (packages/ml-scheduler/src/storage/model-storage.ts)
   ServerSideEncryption: "AES256" - MinIO community edition does not support KMS.
   Fix: Removed ServerSideEncryption param. SHA-256 checksum integrity preserved.

2. MISSING ENV VARS (apps/api/.env)
   S3_ENDPOINT, AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY not loaded by API.
   Fix: Added vars to apps/api/.env and passed explicitly at API startup.

3. NODE ID MISMATCH (scripts/fl-simulator.ts)
   Simulator used string shortnames; DB requires real UUID from edge_nodes.id.
   Fix: Updated NODE_IDS with real UUIDs queried from the database.

4. MULTIPART UPLOAD INCOMPATIBILITY (scripts/fl-simulator.ts)
   Node 22 native fetch() does not stream form-data library objects.
   Fix: Rewrote submitWeights() using Node.js http.request() with manual
        multipart/form-data boundary construction.
